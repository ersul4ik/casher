# Развёртывание: от нуля до работающего бота

Всё бесплатно и бессрочно, банковская карта не нужна ни на одном шаге.
Времени — примерно 20 минут.

**Что понадобится:** аккаунт Telegram, аккаунт GitHub, почта для регистрации на Neon и Render.

Итог: бот живёт на Render, данные — в Postgres на Neon, пинговалка с cron-job.org не даёт
инстансу заснуть.

---

## Шаг 1. Создать бота и получить `BOT_TOKEN`

1. В Telegram открыть [@BotFather](https://t.me/BotFather).
2. `/newbot` → имя (любое, например `Мои траты`) → username, обязательно заканчивается на `bot`
   (например `erik_spends_bot`).
3. В ответ придёт строка вида `8123456789:AAH...` — это **`BOT_TOKEN`**. Сохрани, показывается
   один раз (перевыпуск — `/token` у BotFather).

Заодно можно сделать бота приятнее: `/setdescription`, `/setuserpic`.

---

## Шаг 2. Завести базу на Neon и получить `DATABASE_URL`

1. Зайти на [neon.com](https://neon.com) → **Sign up** (проще всего через GitHub).
2. **Create project**: имя `cacher`, регион выбрать ближайший (`AWS eu-central-1 (Frankfurt)`),
   версию Postgres оставить по умолчанию.
3. После создания откроется **Connection string**. Скопировать целиком строку вида:

   ```
   postgresql://neondb_owner:НЕКИЙ_ПАРОЛЬ@ep-xxxx-yyyy.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```

   Это **`DATABASE_URL`**. Копируй как есть — лишние параметры Neon бот вычищает сам.
   Если строка показана с плейсхолдером пароля, рядом есть переключатель **Show password**.

Бесплатный тариф Neon: 0.5 ГБ данных — это сотни тысяч трат, упереться нереально.
Таблицы бот создаст сам при первом запуске, руками ничего выполнять не нужно.

Проверить строку, не дожидаясь деплоя (`BOT_TOKEN` для этого ещё не нужен):

```bash
cd /Users/eriksultanaliev/work/own/cacher
cp .env.example .env          # вписать DATABASE_URL в .env
set -a && source .env && set +a
.venv/bin/python scripts/check_db.py
```

Должно ответить «Связь есть», перечислить таблицы и число пользователей. `.env` лежит в
`.gitignore` и в репозиторий не попадёт — на Render те же значения вводятся в дашборде,
файл туда не нужен.

## Шаг 4. Развернуть на Render

1. [render.com](https://render.com) → **Get Started** → войти через GitHub.
2. **New +** → **Web Service** → **Build and deploy from a Git repository** → выбрать `casher`
   (при первом подключении Render попросит доступ к репозиторию — дать). Так каждый `git push`
   будет автоматически выкатывать новую версию. Альтернатива без автодеплоя: поле
   **Public Git Repository** и адрес `https://github.com/ersul4ik/casher`.
3. Заполнить:

   | Поле | Значение |
   |---|---|
   | Name | `casher-bot` (от него зависит адрес `https://casher-bot.onrender.com`) |
   | Region | Frankfurt |
   | Branch | `main` |
   | Runtime / Language | Python 3 |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `python -m app.main` |
   | Instance Type | **Free** |

4. Раскрыть **Advanced** → **Add Environment Variable** и добавить:

   | Ключ | Значение | Откуда |
   |---|---|---|
   | `BOT_TOKEN` | `8123456789:AAH...` | шаг 1 |
   | `DATABASE_URL` | `postgresql://...neon.tech/neondb?sslmode=require...` | шаг 2 |
   | `BASE_URL` | `https://casher-bot.onrender.com` | имя сервиса из пункта 3 |
   | `WEBHOOK_SECRET` | длинная случайная строка | `python3 -c "import secrets; print(secrets.token_urlsafe(32))"` |
   | `ADMIN_IDS` | твой Telegram id | узнать у [@userinfobot](https://t.me/userinfobot) |
   | `DEFAULT_CURRENCY` | `KGS` | |
   | `DEFAULT_TZ_MINUTES` | `360` | Бишкек, UTC+6 |
   | `PYTHON_VERSION` | `3.12.6` | |

   Там же **Health Check Path**: `/health`.

5. **Create Web Service**. Первая сборка — 2–4 минуты. В логах должно появиться:

   ```
   База готова
   HTTP слушает порт 10000, приём трат на POST /spend
   Вебхук Телеграма: https://casher-bot.onrender.com/tg/...
   ```

`BASE_URL` должен совпадать с реальным адресом сервиса (виден вверху страницы сервиса). Если
Render выдал адрес с суффиксом вида `casher-bot-a1b2.onrender.com`, поправь переменную и нажми
**Manual Deploy → Deploy latest commit**.

> Вместо ручного заполнения можно использовать **New + → Blueprint**: в репозитории лежит
> `render.yaml`, Render подхватит настройки и спросит только секреты.

## Шаг 5. Проверить, что всё живо

1. Открыть своего бота в Telegram, нажать **Start**. Должно прийти приветствие с кнопками и
   отдельным сообщением — личный токен и адрес для шортката.
2. Написать боту `350 кофейня` — трата запишется сразу.
3. Написать `1470` — придёт вопрос с кнопками категорий.
4. Нажать **📊 День** — появится отчёт со стрелками переключения периодов.
5. Проверить приём пушей (токен взять из `/token`):

```bash
curl -X POST https://casher-bot.onrender.com/spend \
  -H "X-Token: <твой токен>" \
  -H "Content-Type: application/json" \
  -d '{"raw": "Успещная операция по QR. Сумма: 1470.00 KGS"}'
```

Ответ `{"status":"ok","id":1,...}`, в Телеграм приходит вопрос с кнопками. Повторный тот же
запрос в пределах 90 секунд вернёт `{"status":"duplicate"}` — так гасятся дубли пушей.

## Шаг 6. Не дать бесплатному инстансу заснуть

Free-сервис Render засыпает после 15 минут без запросов, и первый запрос после паузы идёт
с холодным стартом до минуты. Лечится внешним пингом:

1. [cron-job.org](https://cron-job.org) → регистрация (бесплатно, без карты).
2. **Create cronjob**:
   - Title: `casher keep-alive`
   - URL: `https://casher-bot.onrender.com/health`
   - Schedule: **Every 10 minutes**
3. Save. На вкладке History должны идти ответы `200`.

Бесплатная квота Render — 750 часов в месяц на аккаунт, один сервис круглосуточно занимает 744.
Так что держать «разбуженным» имеет смысл ровно один сервис.

## Шаг 8. Подключить других людей

Сервис многопользовательский. Новому человеку достаточно:

1. Открыть бота и нажать **Start** — запись, категории и личный токен создадутся сами.
2. Взять свой токен командой `/token` и вписать его в свой шорткат (шаг 7).
3. При необходимости поменять валюту и пояс: `/currency USD`, `/tz +3`.

Траты, категории и отчёты у каждого свои. У тебя как у администратора есть `/stats` — число
пользователей, активность за неделю, обороты по валютам, топ по числу трат.

Если бот должен быть доступен не всем, у BotFather есть `/setjoingroups` и приватность, но
проще всего — никому не давать username бота. Ограничения по списку id в коде нет специально:
добавление нового человека не должно требовать передеплоя.

## Где что взять: сводка

| Переменная | Где берётся | Обязательна |
|---|---|---|
| `BOT_TOKEN` | @BotFather → `/newbot` | да |
| `DATABASE_URL` | Neon → Connection string | да |
| `BASE_URL` | адрес сервиса на Render | да на хостинге, нет локально |
| `WEBHOOK_SECRET` | генерируется самому | нет (выведется из токена) |
| `ADMIN_IDS` | @userinfobot | нет |
| `DEFAULT_CURRENCY` | `KGS` | нет |
| `DEFAULT_TZ_MINUTES` | `360` для Бишкека | нет |
| `DEDUP_WINDOW_SECONDS` | `90` | нет |
| `PORT` | подставляет Render | нет |

## Если что-то не работает

| Симптом | Причина и лечение |
|---|---|
| Бот молчит на `/start` | `BASE_URL` не совпадает с адресом сервиса. Поправить и сделать Manual Deploy. |
| В логах `Не задана обязательная переменная окружения` | не добавлена переменная на шаге 4. |
| В логах ошибка подключения к базе | `DATABASE_URL` скопирован с плейсхолдером пароля вместо самого пароля. |
| `curl` возвращает `403 bad token` | в `X-Token` попал не тот токен; актуальный — в `/token`. |
| `curl` возвращает `400 no amount` | в `raw` нет распознаваемой суммы; прислать `amount` явно. |
| Первый запрос после паузы идёт ~минуту | инстанс засыпал, см. шаг 6. |
| Трата записалась, но сообщение не пришло | Телеграм был недоступен; трата не потеряна — `/pending`. |

Логи: страница сервиса на Render → вкладка **Logs**.

## Запасные площадки

Всё, что нужно для переезда, уже лежит в репозитории — `Dockerfile`. Код не меняется,
переменные окружения те же.

| Площадка | Плюсы | Минусы |
|---|---|---|
| **Koyeb** | деплой из того же репозитория, free-инстанс | квоты меняются, бывает засыпание |
| **Fly.io** | быстро, `fly launch` подхватит Dockerfile | бесплатного тарифа по сути нет, от ~$5/мес |
| **Oracle Cloud Always Free** | 4 ядра ARM и 24 ГБ RAM навсегда, ничего не засыпает | нужна привязка карты, сервер администрируешь сам |
| **Google Cloud Run** | щедрый бесплатный лимит, не требует keep-alive | нужен биллинг-аккаунт с картой |

Базу при переезде трогать не нужно: Neon живёт отдельно, достаточно перенести `DATABASE_URL`.
